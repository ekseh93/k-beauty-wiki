# 관리자 인증·콘텐츠 검수 E2E 체크리스트

이 문서는 배포된 관리자 화면에서 Cognito 인증과 콘텐츠 공개 보호를 한 번 확인하기 위한 운영 체크리스트다. 비밀번호와 초대 메일의 내용은 저장소에 기록하지 않는다.

## 사전 조건

- GitHub Actions의 `ADMIN_EMAIL` Secret이 등록되어 있다.
- 최신 `Deploy AWS` 워크플로가 성공했다.
- Cognito 초대 메일을 받을 수 있다.
- 관리자는 Cognito `admin` 그룹에 속해 있다.

## 1. 최초 로그인

1. Cognito 초대 메일을 확인한다.
2. 배포된 [`/admin`](https://main.d1ece7jdtq0bus.amplifyapp.com/admin) 페이지를 연다.
3. 초대된 이메일과 임시 비밀번호로 로그인한다.
4. 최초 로그인에서 새 비밀번호를 설정한다.
5. `관리자 로그인에 성공했습니다.`와 `Cognito 인증 완료` 표시를 확인한다.

## 1-1. 로그인 후 비밀번호 변경

1. 관리자 화면의 `관리자 비밀번호 변경` 영역을 확인한다.
2. 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 직접 입력한다.
3. `비밀번호 변경`을 실행하고 성공 메시지를 확인한다.
4. 로그아웃 후 새 비밀번호로 다시 로그인되는지 확인한다.

비밀번호는 브라우저 자동 저장이나 검증 결과 기록에 남기지 않는다. 비밀번호 변경 제출은 관리자가 직접 수행한다.

## 2. 검수 대기 콘텐츠 등록

출처를 확인한 콘텐츠 하나를 다음 조건으로 저장한다.

- 상태: `review`
- `isFixture`: `false`
- 일본어 제목, 한국어 원명, slug, 요약, 본문
- 출처 제목과 URL
- 출처 유형, 권리 상태, 수집 방식
- 최종 확인일
- 콘텐츠 유형에 맞는 구조화된 상세 필드

첫 검증에는 공식 제품 페이지를 출처로 사용하는 스킨케어 제품을 권장한다. 커뮤니티 리뷰를 추가하는 경우 원문을 복사하지 않고, 최소 5개 게시글 표본·독립 출처·집계일·독자적인 요약만 기록한다.

## 3. 공개 차단 확인

1. 관리자 화면의 등록 콘텐츠 목록에 `review` 항목이 나타나는지 확인한다.
2. 공개 콘텐츠 목록과 공개 API에 해당 항목이 나타나지 않는지 확인한다.
3. 출처, 최종 확인일, 권리 상태, 필수 상세 필드를 보완한다.

## 4. 공개 전환 확인

1. 검수된 콘텐츠만 `published` 상태로 저장한다.
2. 공개 콘텐츠 목록과 상세 페이지에서 일본어 제목, 한국어 원명, 출처, 최종 확인일이 표시되는지 확인한다.
3. 잘못된 필드나 출처가 있으면 즉시 `review`로 되돌리고 정정 사유를 기록한다.

## 결과 기록

검증 결과는 다음 항목만 기록한다.

- 실행일
- 검증한 slug
- 콘텐츠 상태 변화
- 공개 API 노출 여부
- 확인한 출처 URL
- 실패한 경우의 오류와 후속 조치

이메일 주소, 비밀번호, Cognito 토큰은 기록하지 않는다.

## 자동 회귀 테스트

실제 AWS 계정의 콘텐츠를 변경하지 않는 모의 테스트로 관리자 API의 경계를 확인한다.

```powershell
pnpm test
```

- `review` 콘텐츠는 리뷰 근거와 함께 저장되고 revision이 생성되는지 확인한다.
- 커뮤니티 리뷰 출처에 근거가 없으면 `422`로 거부되고 DynamoDB 쓰기가 발생하지 않는지 확인한다.
- 출처 권리가 `needs-review`인 콘텐츠를 `published`로 전환하면 `422`로 거부되고 DynamoDB 쓰기가 발생하지 않는지 확인한다.
- 잘못된 출처·리뷰 근거 필드는 서버 예외가 아니라 검수 오류로 반환되는지 확인한다.
